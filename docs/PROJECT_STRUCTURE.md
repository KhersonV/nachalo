# Project structure

Current tracked and untracked project files on `refactor/project-cleanup`. Generated output and installed dependencies are excluded. Paths in this tree are relative to the repository root.

## Legacy cleanup

- Removed the square map generator, in-memory `MatchState` restoration, square match HTTP/WS flow, square combat and turn handlers, old React renderer and Redux store, square fixtures, and tests dedicated to that runtime.
- `/game` now loads an existing HEX snapshot and renders `HexGameController`. Retired square snapshots receive HTTP 410; the database row and match history remain untouched.
- Kept the shared combat formulas in `handlers/combat_shared.go`, persisted combat result calculations in `game/results.go`, final reward parsing in `repository/final_rewards.go`, and the PostgreSQL match command ledger used by HEX.
- Moved catacomb prop previews and monster concept references into `assets-source`. Moved source UI PNGs into `assets-source/ui`, and placed production WebP hero art under `public/assets/ui/heroes/{portraits,fullbody}` and marketing banners under `public/assets/ui/marketing`. Updated frontend references.
- Kept `public/guardian`, other hero sprites, `public/main_resources`, `public/monsters`, `public/equipment`, and related seed URLs: these paths appear in persisted PostgreSQL profile, resource, monster, and equipment records. Removing them safely needs a separate data migration.
- Kept mixed repository persistence modules such as `repository/matches.go`, `match_map_cells.go`, and `models/geometry.go` where old square parsing still supports stored data or where HEX and match history share database structures. Historical migration and design documents are retained as records of earlier work.
- No migration against a database has been run; there are no empty project directories in this file inventory.
