# UI Stage A — план реализации редизайна

План не запускает работу и не меняет приложение. Опирается на [реестр](01_FUNCTIONAL_INVENTORY.md), [аудит](02_ARCHITECTURE_AUDIT.md) и [целевую структуру](03_TARGET_UX_ARCHITECTURE.md). Каждый этап должен выпускаться отдельно с проверкой прямых URL и сохранением сценариев. **Порядок 1→9** минимизирует риск: сначала общая оболочка/состояния, затем подготовка к матчу, постоянные ресурсы и социальные экраны, затем HUD поверх уже стабильных контрактов.

## Матрица сквозных сценариев

| Сценарий | Обязательная цепочка | Текущий архитектурный пробел для проверки |
|---|---|---|
| A — подготовка | Base активирует героя → Inventory экипирует → Shop покупает → Modes сохраняет loadout, party/режим/join → глобальная модалка → `/game` | Актуальность героя/баланса/склада между страницами; два координатора матча. |
| B — развитие | HUD результат → History детали/награды → Base постройка/найм → Inventory | Результат погибшего HEX до общего финала, история после финала, не обещать UI Library research. |
| C — торговля | Shop buy/sell → баланс/инвентарь → Inventory/Base | Sell доступен для gear, зелёный gear buy пока заглушка; тестировать ошибки сервера и экипированный предмет. |
| D — матч | Войти в HEX → q/r move/attack/item/build → timer/уведомление → exit/death → result → Lobby | Туман, конкурентные WS/HTTP обновления, double-submit, reconnect, продолжение матча после смерти одного. |

## Правило выпуска каждого этапа

1. До изменения UI зафиксировать существующий путь, API и data contract по строкам реестра.
2. Держать новый вид поверх старого поведения: один домен за раз, без изменения серверных правил или миграций ради дизайна.
3. После этапа проверить прямой URL, загрузку, пусто, ошибку, disabled и мобильную ширину.
4. Отдельно отмечать статус `PLACEHOLDER`/`UNCLEAR`; внешний вид не должен утверждать доступность функции.
5. При нарушении сценария остановить следующий этап и исправить регрессию в текущем.

**Ближайший Stage B:** выполнить этап 1: токены и Lobby shell на существующих шести маршрутах, с доступными кнопками/полями/диалогами и сохранённым `GlobalMatchListener`. До перевода Modes на новый координатор снять ручную базовую проверку соло/party и фонового нахождения матча. Не начинать HUD или 3D на Stage B.
